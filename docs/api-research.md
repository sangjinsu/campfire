# 공식 API 조사 (2026-10-18)

사용 버전은 Cargo.lock으로 최종 확인한다. 조회 당시 latest는 Tokio 1.53.3, Axum 0.8.9이나 로컬에 공식 배포 소스로 확인한 버전은 Tokio 1.52.3, Axum 0.7.4, getrandom 0.3.4, sha2 0.10.9이다. Axum 0.7.4는 tokio-tungstenite ^0.21을 사용한다. 아래 계약은 version-specific 문서와 로컬 crate의 rustdoc/소스를 확인했다.

- [Tokio bounded mpsc](https://docs.rs/tokio/1.52.3/tokio/sync/mpsc/fn.channel.html): capacity는 1 이상이어야 한다. `Sender::try_send`의 `TrySendError::Full`과 `Closed`를 구분한다. 공유 입력 포화는 사용자 위반으로 계산하지 않는다. `send().await`는 여유 공간을 기다리므로 룸 출력 경로에 사용하면 느린 연결이 tick을 막을 수 있다.
- [Tokio watch](https://docs.rs/tokio/1.52.3/tokio/sync/watch/index.html): 최신 값 하나만 유지한다. `send_replace`는 receiver가 없어도 새 값을 저장한다. `Receiver::changed`와 `borrow_and_update`를 사용하고 borrowed `Ref`는 await 전에 clone/drop한다. full sync와 reliable event는 별도 bounded mpsc로 보낸다.
- [Tokio JoinSet](https://docs.rs/tokio/1.52.3/tokio/task/struct.JoinSet.html#method.join_next_with_id): `join_next_with_id`는 `Option<Result<(Id,T),JoinError>>`; 오류 task ID는 `JoinError::id()`로 조회한다. `is_panic()`으로 unwind를 식별하고 task ID→room instance 매핑으로 directory/session을 정리한다. `join_all`은 panic을 다시 전파하므로 개별 룸 panic 감독에 사용하지 않는다. `abort_all()` 뒤에도 join을 drain해야 한다.
- [Tokio pause](https://docs.rs/tokio/1.52.3/tokio/time/fn.pause.html), [advance](https://docs.rs/tokio/1.52.3/tokio/time/fn.advance.html): `test-util` feature와 current-thread runtime이 필요하다. 만료와 tick은 `tokio::time::Instant`로 계산한다. paused runtime은 idle 상태에서 시간을 자동 진행하므로 TCP I/O 통합 검증은 실제 시계, 결정성/만료 단위 검증은 manual clock으로 나눈다. `advance` 후 깨어난 task들이 완료됐다고 가정하지 않고 yield/확인한다.
- [Axum 0.7.4 WebSocketUpgrade](https://docs.rs/axum/0.7.4/axum/extract/ws/struct.WebSocketUpgrade.html): HTTP/1.1 GET route 및 `ws` feature. `max_message_size(16384)`와 `max_frame_size(16384)`를 함께 지정해 fragmentation 우회를 막는다. 기본 message/frame 제한은 각각 64MiB/16MiB로 사양보다 크다. `.write_buffer_size(0)`와 유한한 `.max_write_buffer_size(...)`를 사용할 수 있으며 max는 write buffer+최대 message보다 커야 한다. `on_failed_upgrade`에서 실패 전 connection permit을 회수해야 한다. `on_upgrade` callback과 future는 Send+'static이다. `Message::Text`는 0.7 계열에서 String이며 최신 0.8과 혼동하지 않는다.
- [Tungstenite 0.21 WebSocket](https://docs.rs/tungstenite/0.21.0/tungstenite/protocol/struct.WebSocket.html): Ping/Close에 대한 자동 응답은 다음 read/write/flush에서 진행된다. 수동 Pong 중복 전송을 피하고 Close handshake는 flush/read로 완료한다. `WriteBufferFull`은 반환된 메시지를 포함하며 연결별 overload 처리 대상이다. WebSocket 최대 frame 단계의 Capacity 오류 뒤 연결을 계속 쓸 수 있다고 가정하지 않는다. 따라서 초과 frame은 transport가 즉시 종료할 수 있고 반복 초과를 같은 연결에서 세는 정책에는 앱 상한과 더 큰 transport 안전 상한 구분이 필요하다.
- [getrandom 0.3.4 fill](https://docs.rs/getrandom/0.3.4/getrandom/fn.fill.html): `getrandom::fill(&mut [u8;32]) -> Result<(),Error>`가 OS 난수를 채운다. 실패/부분 읽기는 오류이며 실패한 버퍼를 토큰으로 쓰지 않는다. base64url/hex로 인코딩하고 plaintext를 저장하거나 로그하지 않는다.
- [sha2 0.10.9](https://docs.rs/sha2/0.10.9/sha2/): `use sha2::{Digest,Sha256}; let digest=Sha256::digest(token.as_bytes());` 공식 예제 확인. 256-bit 고엔트로피 토큰의 검증용 해시를 저장한다. 사용자 비밀번호 저장과는 다른 용도다.

근거 경로: `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/{tokio-1.52.3,getrandom-0.3.4,sha2-0.10.9}/src/`, `~/.cargo/registry/src/index.crates.io-6f17d22bba15001f/axum-0.7.4/src/extract/ws.rs`. gstack browse는 sandbox localhost bind EPERM으로 최초 실패했고 승인된 escalation으로 공개 docs.rs 문서 HTTP 200 조회에 성공했다. 이 수치/프로토콜은 라이브러리의 규약이 아니라 Campfire 사양이다.

## Account / command / private-state extension 근거 (2026-10-18)

이 절은 Cargo.lock의 Axum 0.8.9, Tokio 1.53.3, Serde 1.0.229, http 1.5.0을 기준으로 한다. gstack browse의 별도 `/tmp/campfire-docs-browse/browse.json` 세션으로 아래 공식 문서의 HTTP 200 및 본문을 확인했다. 최초 sandbox 실행은 localhost bind `EPERM`으로 실패했고 승인된 escalation에서 성공했다. 기존 shared browser daemon은 변경하지 않았다. 로컬 공식 crate 배포 소스의 rustdoc도 교차 확인했다.

### 확인한 API 계약

- [Rust Reference: dyn compatibility](https://doc.rust-lang.org/reference/items/traits.html#dyn-compatibility): dispatch 가능한 trait method에 lifetime parameter는 허용되지만 type generic parameter나 opaque return type은 허용되지 않는다. `async fn`과 반환 위치 `impl Trait`는 hidden/opaque future를 반환하므로 `Arc<dyn AccountAuthenticator>`의 호출 가능한 method로 직접 쓰지 않는다. `fn authenticate<'a>(&'a self, game_id: &'a str, credential: &'a str) -> Pin<Box<dyn Future<Output = Result<AccountGrant, AuthError>> + Send + 'a>>` 형태로 주입할 수 있다. verifier 자체는 `Send + Sync + 'static`으로 제한한다.
- [Tokio timeout](https://docs.rs/tokio/1.53.3/tokio/time/fn.timeout.html): `timeout(duration, future).await`는 `Result<T, Elapsed>`를 반환하며 시간 초과 시 내부 future를 drop한다. 실행이 yield하지 않으면 제한 시간을 넘겨 완료할 수 있으므로 host verifier는 blocking I/O나 CPU 작업으로 runtime을 막으면 안 된다. 외부에서 별도 spawn한 task까지 자동 취소된다고 약속하지 않는다. 완료 후 runtime의 자체 deadline도 다시 검사한다.
- [Axum DefaultBodyLimit](https://docs.rs/axum/0.8.9/axum/extract/struct.DefaultBodyLimit.html): 기본 2MB 제한은 `Bytes`와 이를 사용하는 `Json`, `String`, `Form`에 적용된다. credential JSON endpoint에는 route별 `.layer(DefaultBodyLimit::max(...))`로 작은 명시적 제한을 둔다. body를 직접 polling하는 custom extractor에는 이 제한이 자동 적용되지 않는다.
- [Axum JsonRejection](https://docs.rs/axum/0.8.9/axum/extract/rejection/enum.JsonRejection.html): non-exhaustive enum이며 JSON 문법·필드·content type·bytes 오류를 포함한다. `.status()`를 확인해 payload 413과 누락/미지원 Content-Type 415는 보존하고 JSON 문법·schema 오류는 Campfire 계약인 400으로 정규화하여 공통 JSON 오류 envelope로 반환한다. `.body_text()`나 디버그 출력에 credential이 포함될 가능성을 만들지 않도록 클라이언트와 로그에는 고정된 안전 메시지를 사용한다.
- [http StatusCode](https://docs.rs/http/1.5.0/http/status/struct.StatusCode.html): `UNAUTHORIZED`(401), `FORBIDDEN`(403), `PAYLOAD_TOO_LARGE`(413), `UNSUPPORTED_MEDIA_TYPE`(415), `TOO_MANY_REQUESTS`(429), `SERVICE_UNAVAILABLE`(503)가 제공된다. Campfire의 실제 계약은 credential 검증 실패 401, 등록되지 않은 game 404, verifier 미설정 501, verifier 장애·잘못된 grant 503, verifier timeout 504이며 protocol 문서와 테스트에 일치시킨다.
- [Tokio bounded mpsc](https://docs.rs/tokio/1.53.3/tokio/sync/mpsc/fn.channel.html), [Sender::try_send](https://docs.rs/tokio/1.53.3/tokio/sync/mpsc/struct.Sender.html#method.try_send): capacity는 1 이상이며 전송 순서대로 receiver에 전달된다. `try_send`는 queue가 차면 기다리지 않고 `Full`, receiver가 사라지면 `Closed`를 반환한다. 단발 명령은 전용 bounded FIFO로 보내고 포화 시 재시도 가능한 오류를 보낸다. 최신 입력 하나만 저장하는 coalescing slot이나 snapshot용 watch에 넣으면 명령이 사라진다.
- [Serde container attributes](https://serde.rs/container-attrs.html): `deny_unknown_fields`는 JSON의 알 수 없는 필드를 거절한다. 계정 발급 JSON에 client `subject`, `player_id`, `claims`를 받지 않으며 credential만 허용한다. `flatten`과 조합하지 않는다.
- [OpenID Connect Core: ID Token](https://openid.net/specs/openid-connect-core-1_0.html#IDToken), [Subject Identifier Types](https://openid.net/specs/openid-connect-core-1_0.html#SubjectIDTypes): `sub`는 issuer 안에서의 식별자이며 대소문자를 구분한다. OIDC를 쓰는 host verifier는 signature/issuer/audience/expiry 등 provider의 검증 계약을 책임진다. Campfire는 provider를 임의로 가정하거나 JWT payload decode를 검증으로 취급하지 않는다. 런타임 계정 key에는 `(game_id, issuer, subject)`를 사용한다. email/display name을 안정 식별자로 사용하지 않는다.

### Runtime 보안 계약과 필수 검증

아래는 위 API로 구현하는 Campfire 정책이며 해당 라이브러리가 자동 제공하는 보장은 아니다.

1. **서버 검증 신원과 단일 계정 세션**: host의 async verifier가 `AccountGrant { identity: AccountIdentity { issuer, subject, claims }, valid_for }`를 반환한다. credential·claims를 기본 Debug/log나 오류 응답에 노출하지 않는다. 동일 `(game_id, issuer, subject)`의 활성 session을 rotation할 때 이전 token과 connection을 무효화하고 안정된 player ID와 seat를 명시적으로 이전한다. 서로 다른 game/issuer/subject는 충돌하지 않아야 한다. 이전 queued generation으로 명령을 실행하거나 이전 disconnect가 새 연결을 해제하지 못하는지 검증한다.
2. **인증 자원·수명 제한**: 기존 인증 semaphore/rate policy와 별개로 우회되는 무제한 경로를 만들지 않는다. state mutex를 잡은 채 외부 verifier를 await하지 않는다. verifier 호출 전 `auth_started`를 기록하고, conservative 계약으로 deadline을 `auth_started + min(valid_for, guest_ttl)`로 계산한다. checked arithmetic을 쓰고 완료 시 만료·shutdown을 다시 검사한다. host가 `valid_for`를 요청 시작 시점 기준 유효기간으로 반환한다는 약정을 명시한다. 지연 검증, zero/expired grant, 과대 duration, timeout 후 session 미발급, 동시에 몰린 검증의 제한, verifier 오류 redaction을 테스트한다.
3. **명령의 terminal 결과**: room actor가 membership, generation, token deadline을 확인하고 game validation과 mutation을 같은 actor turn에서 처리한다. enqueue 성공을 mutation 성공으로 응답하지 않는다. validation 실패에 mutation이 없고, tick 사이 두 명령이 모두 처리되며, queue 포화·stale connection·expired account·wrong room instance에서 mutation이 없는지 검사한다. 비동기 timeout 또는 연결 해제로 reply receiver가 사라져도 이미 처리된 명령의 결과 ledger는 유지한다.
4. **재전송의 범위**: `command_seq` highwater와 bounded result ledger는 membership 수명에 귀속하고 reconnect에도 유지한다. 동일 sequence/body는 기록된 terminal 결과를 반환하며 다시 실행하지 않는다. 동일 sequence/다른 body는 conflict, cache에서 퇴출된 과거 sequence는 stale로 거절한다. 서로 다른 request ID, 다른 connection, validation 실패 재전송, 순서 역전·큰 jump·`u64::MAX`·leave/rejoin을 검증한다. bounded replay는 무한한 exactly-once 보장으로 설명하지 않는다.
5. **수신자별 private projection**: public `snapshot()`과 별도의 `private_state(player_id)`를 사용한다. join/resume full sync, periodic snapshot, command result, replay cache의 모든 전송 경로에서 수신자를 일치시킨다. private field는 broadcast용 단일 공용 Value에 넣지 않는다. 서로 다른 secret을 가진 두 player, reconnect, room leave/rejoin, room ID 재사용, old connection takeover, result 재전송에서 상대 secret이나 이전 room private state가 노출되지 않는지 검사한다. host game callback은 신뢰된 코드이므로 그 자체의 잘못된 public projection까지 framework가 자동 은폐한다고 약속하지 않는다.

근거 소스: `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/axum-0.8.9/src/json.rs`, `axum-core-0.5.6/src/extract/default_body_limit.rs`, `tokio-1.53.3/src/time/timeout.rs`, `http-1.5.0/src/status.rs`. 이 조사 단계에서는 production 설정이나 실행 중 서비스를 변경하지 않았다.

최종 소스 대조: 계정 rotation은 `RotationDecision` 공유 mutex의 Pending/Committed/Aborted 결정과 `PendingRotation::Drop` abort로 취소·만료를 조정한다. candidate grace는 commit 전 기존 seat에 적용하지 않으며 마지막 await 후 old-seat valid_until·새 TTL·shutdown을 확인해 공유 decision을 commit하고 await 없이 token map을 교체한다. actor는 expire/tick/control/data 전에 결정을 반영한다. request/payload fingerprint는 clone의 `sort_all_objects()`로 중첩 object key를 정렬해 `serde_json/preserve_order`에서도 key 순서에 독립적이고 배열 순서는 구별한다. 이는 위 라이브러리 API를 사용하는 Campfire 구현 계약이며 공식 API가 제공하는 exactly-once 보장이 아니다.
